# 紫鸟窗口生命周期（唯一依据）

本文件是紫鸟窗口「登记借号 → 排队叫号 → 催债回收 → 归还关窗」的唯一规则。
改动 `resources/`、`queueing/` 里与窗口有关的代码前，先对照本文件；
实现与本文件冲突时，先改实现，或者先改本文件并说明理由。

## 流程

任务 → 执行 → 需要紫鸟 → 去紫鸟模块登记借号 → 借到就用 / 借不到排队等叫号
→ 催债人催还、没回应强制回收 → 用完登记归还、关窗 → 叫下一个 → 任务结束。

1. 任务开始，执行。
2. 执行需要紫鸟窗口：向紫鸟模块登记借号（建租约）。
3. 借不到（店铺被别的执行借走，或窗口容量满）：进排队，等叫号；
   不同店铺分开排；**不判失败**。
4. 借到：拿到窗口，执行使用。
5. 催债人（唯一的定时回收者）：租约到期或执行结束 → 催还；
   没有回应 → **强制回收关窗**。
6. 用完：登记归还 → 关窗并确认 → 释放容量 → 叫下一个。
7. 本子上没有的窗口（不是工作台开的）：不动，报错让人处理。
8. 任务结束。

## 状态

租约只有五种状态：

| 状态 | 含义 |
|---|---|
| `OPENING` | 登记中，窗口还没确认打开 |
| `ACTIVE` | 借出，带到期时间 |
| `CLOSING` | 回收中，关窗还没确认 |
| `RETURNED` | 已归还，关窗已确认 |
| `FAILED` | 借失败 |

没有 `UNKNOWN`，没有 `blocked` 标记。

## 规则

- 借不到只排队，不失败。排队原因写 `wait_reason`，界面可见。
- 关窗失败留在 `CLOSING` 并记原因；催债人定期重试，确认关闭后才变 `RETURNED`。
  这期间该店铺的借用请求排队等叫号，不产生新状态。
- 只有工作台开的窗口会被回收；本子上没有的窗口不动，借用时报错让人处理。
- 所有回收动作只由催债人执行：到期、执行结束、服务重启后的遗留租约，都交给催债人。
- 服务重启不单独回收，只把 `OPENING/ACTIVE/CLOSING` 的遗留租约交给催债人。
- 归还必须确认关闭（关窗 + 核验）才算 `RETURNED`；没确认不能叫下一个。

## 术语

- **登记/借号**：建租约。
- **催债人**：定时检查租约并回收的唯一定时任务。
- **叫号**：租约 `RETURNED` 后，排队中的借用请求按顺序继续。
- **本子**：`resource_lease` / `resource_info` 记录。
- **回收**：关闭窗口并确认关闭。
